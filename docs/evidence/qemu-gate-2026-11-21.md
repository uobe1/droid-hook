## 工作流结构

`.github/workflows/qemu-gate.yml` (dispatch-only):

- `image` job: DDK 容器 `ghcr.io/ylarod/ddk-min:android16-6.12-20260828` 内
  `make -C /opt/ddk/kdir/android16-6.12 M=$GITHUB_WORKSPACE modules`, 再
  `objcopy -O binary -R .note -R .note.gnu.build-id -R .comment -S vmlinux Image`;
  硬断言 `.ko` 存在、`modinfo -F name`=`droid_hook`、`modinfo -F vermagic` 非空
- `boot` job: `ubuntu-latest` 装 `qemu-system-arm`, 用固定 sha256
  (`041fa34a…f3de`) 的 Alpine 3.20.3 arm64 minirootfs 打包 initramfs, 内含
  `tests/qemu/init-droid-hook`:
  - `insmod /modules/droid_hook.ko selftest=1`
  - `/sys/module/droid_hook` 存在; dmesg 出现 `DH_SELFTEST_OK`
  - `rmmod droid_hook`; `/sys/module/droid_hook` 消失; dmesg 出现 `droid_hook: unloaded`
  - `/proc/kallsyms` 无 `dh_ctx_init` 残留; dmesg 无
    `WARNING:/Oops/BUG:/Call trace/Kernel panic`
  - 成功打印 `DH_QEMU_UNLOADED` / `DH_QEMU_OK`; 任一步失败打印 `DH_QEMU_FAIL <tag>`
- host 侧硬断言 `DH_QEMU_BOOT / DH_SELFTEST_OK / DH_QEMU_UNLOADED / DH_QEMU_OK`, 并对
  `DH_QEMU_FAIL|Kernel panic|Oops|BUG:|CFI failure|Unknown symbol|invalid module format|
  insmod: can't insert|WARNING:` 判失败; 无 `|| true`
- 串口日志 `qemu.log` 以 `if: always()` 上传 (artifact `droid-hook-qemu-log`)

## Run 记录

| run id | headSha | 结果 | 明细 |

| `44909207598` | `d1a0f19` | **failure (boot)** | `image` job 1m03s 通过 (ko+Image 产出); `boot` job 18s, `qemu-system-aarch64` 立即退出: `failed to find romfile "efi-virtio.rom"`, `qemu_rc=1` |
| `44909471977` | `f77a90e` | **failure (selftest)** | `image` job 1m24s 通过; `boot` job 20s 真实启动: `DH_QEMU_BOOT 6.12.76-4k` → `insmod` → `DH_SELFTEST_FAIL:relocate_ret` → `DH_QEMU_FAIL insmod`; `qemu_rc=0`, host 断言失败; 串口日志 artifact 已上传 |

- 失败 1 原因: `Install QEMU` 的包列表漏了 `ipxe-qemu*`, 而 `efi-virtio.rom` 由它提供.
  这是环境缺包, 不是内核/模块问题; `image` job 已证明 `.ko` 在 DDK 内核树下构建成功.
  修复: `PKGS` 加入 `ipxe-qemu ipxe-qemu-256k-compat-efi-roms`; 串口日志上传逻辑不变.
- 失败 2 原因 (门控真正抓到的东西): 模块已成功 `insmod` 并执行 `selftest=1`, 但
  `dh_module.c` 自检把 "NOP 重定位" 期望成 `DH_OK`; 库契约是 `DH_E_OPNOTSUPP`
  (host `tests/host/test_dh_insn.py` 亦断言 -95, 本机最小程序实测 `ret=-95`).
  host 90 项测试不编译/运行 `dh_module.c`, 所以这个不一致只能在真实内核里暴露.
- 修复: 自检改为正向断言受支持的 B 重定位 (0x14000100 @0x1000, 重定位到 0x2000 →
  `0x17FFFD00`, 已用 host 程序实测) + 反向断言 NOP 被拒绝 (`DH_E_OPNOTSUPP`).
- 两处变更集的重试额度均已用尽, **本轮不再派发**; selftest 修复只做了 host 侧等价验证,
  `dh_module.c` 本机缺 `asm/cpucap-defs.h` 无法语法检查, 复验待下一轮.
